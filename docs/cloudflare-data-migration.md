# 博客数据服务迁移

## 决策与额度门槛（2026-09-10）

仅迁移本博客的数据。Sanity、Clerk、Resend 和其他站点保持原服务。Neon 四张表共 122 行（评论 32、留言 29、订阅者 57、邮件 4），PostgreSQL 表及索引合计约 272 KiB。Redis 16189 个键中 16030 个是限流数据，159 个为持久状态或缓存。完整原始备份存于 git 忽略的 `.migration-private`，权限 0700/0600；报告不包含用户邮箱、订阅 token 或正文。

通过 Cloudflare GraphQL 获取 2026-08-10 至 2026-09-09 全域名流量，原始汇总见 `cloudflare-data-usage-baseline.json`。每日最大 14438 请求、1492 页面浏览；这是包含其他子域的保守上界，并非博客 API 请求数。账户此前没有 D1 数据库。预算采用 Cloudflare 全域流量上界，不依赖 Upstash 后台历史报表。

[D1 官方价格](https://developers.cloudflare.com/d1/platform/pricing/)：免费档每天读取 500 万行、写入 10 万行，总存储 5 GB。索引更新也计写入；超额会拒绝查询。付费账户的包含额度与免费档不同，不能把“本次迁移低于免费档基准”理解为账户完全免费或自动封顶。

预算：普通防刷采用原生限流，不写 D1；一次文章访问最多更新总浏览量、文章浏览量、访客位置三个状态。按每项含主键索引保守计两行，每天峰值浏览量约 8952 行写入。即把全域峰值每次 HTTP 请求均当作访问，也约 86628 行，低于 10 万。评论、留言和订阅增长目前远小于此量级；读请求使用主键/业务索引，列表有条数限制，公开文章统计缓存 60 秒。当前迁移通过额度门槛；未来流量增长仍需通过 D1 Metrics 观察实际 rows_read/rows_written，不能保证任意攻击或增长下免费。

## 模块设计

- Neon → D1：保留整数 ID、父回复关联、JSON、nullable 字段；时间转换为 UTC 毫秒，Drizzle 返回 Date。PostgreSQL 日期统计替换为 SQLite UTC 日期边界。
- Redis 业务状态 → D1 `blog_state`：JSON 值、过期时间，主键查询；浏览量和点赞使用 SQL 原子更新，访问批次使用 D1 batch 事务。
- Redis 限流 → Workers 原生 Rate Limiting binding：30/10 秒普通接口、10/10 秒评论、1/10 秒订阅、5/10 秒活动。活动接口原为 5/5 秒，调整为更保守的 5/10 秒，因为原生只支持 10 或 60 秒。
- 原生限流为节点内最终一致的防刷，不是全球严格配额。与原 Upstash 滑动窗口语义不同，不能复用于计费或库存。业务计数仍在 D1 原子更新。
- favicon 保留 TTL 语义；过期值不返回。`activity:app` 当前源库无值，接口仍返回 null；外部写入器如将来启用，必须另行对接，不能继续写旧 Redis。

参考：[D1 导入注意事项](https://developers.cloudflare.com/d1/best-practices/import-export-data/)、[Drizzle D1](https://orm.drizzle.team/docs/sqlite/connect-cloudflare-d1)、[Workers 限流语义](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)。PostgreSQL dump 不能直接导入 D1，因此使用有字段转换的 JSON 快照生成 SQL。

## 切换及验证门槛

1. 只读导出源数据，隔离本地 D1，逐字段校验后启动 Next 本地服务。
2. 本地验证页面、API、原子并发计数、JSON/时间/ID、评论留言读写与回复；测试邮件不发送给真实用户。
3. 生产构建及本地 workerd 验证通过后，短暂冻结旧版本写入，等待在途请求完成，再导出最终快照。
4. 导入专用远端 D1，逐字段比对；部署 D1 版本，线上逐页和交互验证。
5. 保留旧服务及快照，不删除原库。切换后若 D1 有新写入，回滚必须先同步增量，不能直接回滚 Worker 丢弃新数据。
